# Вимірювання циклу компіляції: FPC, TCC, Clang і GCC

**Статус:** перший успішний hosted-runner вимір отримано; локальний вимір на машині власника ще потрібен.  
**Завдання:** [#115](https://github.com/juv4uk/wsm-os-lisp/issues/115).  
**Запуск:** workflow [Toolchain iteration benchmark](../../actions/workflows/toolchain-iteration-benchmark.yml).

## Що вимірюється

Harness компілює еквівалентні невеликі програми на Pascal і C, запускає кожну та перевіряє однаковий checksum `47999989`.

| Компілятор | Вихідний код | Профіль |
|---|---|---|
| FPC | Pascal | `-O-` |
| TCC | C | стандартний швидкий режим |
| Clang | C | `-O0` |
| GCC | C | `-O0` |

Для кожного компілятора виконуються 15 прогонів за замовчуванням. Перший прогін позначається cold, наступні — warm. Зберігаються compile time, повний build+run time, розмір бінарника, версії компіляторів, хеші вихідних файлів, P50/P90 та сирі семпли.

## Як запустити локально

Потрібні Python 3, FPC, TCC, Clang і GCC:

```sh
python3 benchmarks/toolchain/measure.py
```

Змінні середовища:
- `WSM_TOOLCHAIN_RUNS=15` — кількість прогонів на компілятор (мінімум 5).
- `WSM_TOOLCHAIN_OUT=target/toolchain-iteration-benchmark` — каталог результатів.

## Обмеження інтерпретації

- Це початковий fast-feedback мікроексперимент, а не повний цикл розробки ОС і не benchmark продуктивності мов.
- C-компілятори порівнюються на одному C-файлі; FPC — на еквівалентному Pascal-файлі. Різниця між мовами та runtime залишається фактором.
- Режими без оптимізації обрані для швидкого циклу зворотного зв'язку; це не production-порівняння `-O2`.
- TCC не має тотожного оптимізаційного режиму до GCC/Clang/FPC; результати треба читати як вимір конкретних профілів.
- Однаковий checksum перевіряє результат, але не доводить еквівалентність усіх властивостей реалізацій.
- Результати з GitHub-hosted runner не можна порівнювати безпосередньо з локальною машиною власника. Для рішення щодо щоденного workflow потрібен окремий запуск на його обладнанні з тим самим harness.
- Поточний ASM baseline з [першого виміру](ITERATION-TIME-GATE-SUITE-2026-11-27.md) — 168 ms median assemble+link на іншому середовищі; це лише історична точка відліку, не пряме порівняння з цим workflow.

## Артефакти

Workflow завантажує `samples.tsv` і `summary.json`. Після першого успішного запуску результати мають бути додані сюди з точним SHA workflow run, версіями toolchain і середовищем. До цього числові висновки не робляться.

### Попереднє прочитання

У цьому дуже малому fast-feedback тесті TCC виявився найшвидшим; GCC і FPC близькі за compile time, Clang повільніший. FPC не має автоматичної переваги лише через мову. Різниця у розмірі бінарника значна, але цей hosted Linux test включає FPC RTL і не є freestanding footprint виміром.

Це не фінальний вибір інструментів: runner не є машиною власника, а мікропрограма не відображає розмір реальних компонентів. Наступний крок — повторити harness на машині власника та додати production-профіль з оптимізацією й реальним кодом із репозиторію.
