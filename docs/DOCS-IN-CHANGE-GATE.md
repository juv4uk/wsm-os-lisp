# Gate: документація в тому самому коміті

**Нормативне правило:** зміни в `src/` або `scripts/` мають змінювати `docs/`, `README.md` або `AGENTS.md` у **тому самому коміті**. Пізніший docs-only commit у тому самому push не виправляє попередній code-only commit.

## Алгоритм перевірки

1. Workflow checkout-ить повну історію (`fetch-depth: 0`).
2. `check-docs-in-change.sh` проходить коміти в `base..head` у топологічному порядку.
3. Для кожного коміту обчислюється diff від його першого батька. Для root commit використовується diff від порожнього дерева.
4. Якщо commit змінює `src/` або `scripts/`, у цьому самому diff має бути файл із `docs/`, `README.md` або `AGENTS.md`.
5. Виняток дозволений лише commit message того самого коміту: `DOCS-NOT-REQUIRED: <reason>`. Причина після двокрапки обов'язкова та має містити не лише пробіли.
6. Коміти бічних гілок, що потрапили в merge range, перевіряються окремо; сам merge commit також перевіряється відносно першого батька. Squash commit перевіряється як один інтегрований diff.

## Регресійна матриця

`scripts/test-docs-in-change.sh` створює тимчасові Git-репозиторії й перевіряє 11 сценаріїв: code+docs разом, code-only, code-only з пізнім docs-only, валідний marker у тому самому коміті, marker в іншому коміті, порожній marker, docs-only, порожній range, невалідна split-історія у merge, валідний merge та squash commit.

Workflow запускає цю матрицю перед перевіркою поточного push range. Для `workflow_dispatch` базовий SHA дорівнює поточному SHA, тож перевіряється порожній range після regression harness.

## Поведінка при помилці

Gate завершується ненульовим кодом і називає конкретний commit та code paths без документації. Відсутня локально base/head revision — помилка, а не мовчазний пропуск. Новий ref із нульовим before SHA залишається окремим випадком без порівнюваної історії. Шляхи зіставляються чутливо до регістру; marker приймається лише як окремий рядок commit message, що починається з колонки 1, і лише з непорожньою причиною.
