# ADR-003: Mechanism Below, Policy Above (Rust <-> Lisp Contract)
*ADR-003: Механізм внизу, політика нагорі (Контракт між Rust та Lisp)*

**Date/Дата**: 2026-08-31
**Status/Статус**: Accepted / Прийнято
**Context/Контекст**: The ecosystem requires a clear capability and architectural boundary between the underlying execution layer and the high-level orchestration/semantic layer. We need to ratify the division of responsibilities to avoid overlapping abstractions. / Екосистемі потрібна чітка межа можливостей та архітектури між базовим рівнем виконання та високорівневим рівнем оркестрації/семантики. Нам потрібно затвердити розподіл обов'язків, щоб уникнути дублювання абстракцій.

## 1. The Core Split / Базовий розподіл

**Rust (Mechanism / Механізм):**
Rust owns the long-lived process safety. It manages the runtime, memory allocations, drivers, strictly-typed ABI boundaries, concurrent threads, network sockets (TCP), and capability bounds.
*Rust відповідає за безпеку довготривалого процесу. Він керує середовищем виконання (runtime), виділенням пам'яті, драйверами, строго типізованими межами ABI, паралельними потоками, мережевими сокетами (TCP) та межами повноважень.*

**WSM/Lisp (Policy / Політика):**
Lisp owns the meaning of the system. It defines business rules, orchestration behaviors, guard rules, event classification, composition of capabilities, and UI logic. Policy changes do not require recompiling the Rust substrate.
*Lisp відповідає за сенс системи. Він визначає бізнес-правила, поведінку оркестрації, guard-правила, класифікацію подій, композицію можливостей та логіку UI. Зміна політики не вимагає перекомпіляції Rust-ядра.*

## 2. Boundary Primitive List / Перелік примітивів межі

The explicit boundary list of primitives exposed from Rust to Lisp:
*Явний перелік примітивів, що експонуються з Rust у Lisp:*
- **`spawn`**: Request Rust to execute a scoped subprocess or one-shot task.
- **`send` / `receive`**: Request Rust to transmit/receive structured events over validated TCP connections.
- **`schedule`**: Register a timed callback within the Rust event loop.
- **`write-state` / `read-state`**: Request durable storage of derived state (Rust sanitizes paths).

## 3. Binding to Existing Contracts / Зв'язок із наявними контрактами

This mechanism-policy split anchors to existing wsm-os foundations:
*Цей розподіл механізм-політика спирається на наявні фундаменти wsm-os:*
- **TARGET-ABI.md**: The `wsm-os` ABI remains the strict C-compatible or standard scalar interface. Lisp compiles down to interactions through this ABI.
- **CML IR**: All compute and tensor logic generated by Lisp policy is lowered to CML IR, which Rust securely maps to GPU/CUDA/FPGA.
- **ADR-001 / ADR-002 (Boot Image)**: Rust remains the `boot substrate`, loading the definition capsule (Lisp boot image) which then takes over policy execution.

## 4. Explicit Lisp Prohibitions / Явні заборони для Lisp

To guarantee isolation, the WSM/Lisp layer **MAY NOT**:
*Для гарантування ізоляції, шару WSM/Lisp **СУВОРО ЗАБОРОНЕНО**:*
1. **Raw Pointers**: Access or manipulate raw memory addresses.
2. **Unchecked Device Access**: Open raw block devices `/dev/*` directly; it must request access via a Rust driver primitive.
3. **Foreign Syscalls**: Execute raw OS syscalls directly bypassing the Rust ABI gate.

## 5. Rust+Python vs Rust+Lisp Decision / Порівняння Rust+Python та Rust+Lisp

Historically, Python was used for "policy" (orchestration scripts). We have decided to migrate from Rust+Python to Rust+Lisp.
*Історично Python використовувався для "політики" (оркестраційні скрипти). Ми прийняли рішення перейти від Rust+Python до Rust+Lisp.*

- **Why not Python? / Чому не Python?** Python requires a massive background interpreter, struggles with zero-overhead hot reloading of semantic rules, and creates implicit dependencies outside the project tree.
- **Why Lisp? / Чому Lisp?** Our Lisp (WSM) is directly manageable, compiles to our own CML IR, natively supports `status_at_import` for hot reloading, and acts as a transparent, auditable AST that the Rust daemon can sandbox completely.
