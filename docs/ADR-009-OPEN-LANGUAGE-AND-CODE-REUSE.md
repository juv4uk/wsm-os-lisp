# ADR-009: Відкрита мовна політика та повторне використання коду

**Дата:** 2026-11-27  
**Статус:** ACTIVE OWNER DIRECTIVE — за прямою вказівкою власника в чаті; формальний запис збережено тут  
**Замінює:** мовні заборони та мовні allowlist/denylist у попередніх ADR/AGENTS  
**Пов'язано:** ADR-006, ADR-008, SENS Contract 12.0, `juv4uk/wsm-lazarus`

## 1. Рішення власника

**No blanket language bans.** У проєкті не існує заборонених мов програмування. Це стосується Rust, C, Free Pascal, Assembly, Lisp, Zig, Go, Swift та будь-яких інших мов, нинішніх або майбутніх.

Мова не визначається каталогом: C не обмежується `third_party/`, Pascal — `src/`, а Rust чи будь-яка інша мова не виключається з production лише через назву.

## 2. Як обирати реалізацію

Вибір робиться для конкретного компонента за сукупною вартістю життєвого циклу:

- час від зміни до перевіреного feedback;
- час компіляції, інкрементальної та повної збірки;
- runtime-продуктивність, пам'ять і розмір артефакту;
- бібліотеки, драйвери та готові компоненти;
- ABI/FFI, ownership, layout і складність інтеграції;
- безпека, конкурентність, налагодження та довгострокова підтримка.

Дозвіл використовувати мову не означає, що будь-який її код автоматично придатний. Придатність доводиться тестами, вимірами, перевіркою ABI та позитивними/негативними свідками. Це критерії якості реалізації, а не мовні заборони.

## 3. Повторне використання — перший вибір

Код із репозиторіїв власника можна напряму копіювати, переносити, адаптувати, компонувати й компілювати іншим toolchain, якщо це технічно доречно. Не переписувати працюючий компонент лише через іншу мову або структуру каталогів.

Для кожного перенесення зберігати:
1. точний upstream repository і commit SHA;
2. повний license notice, авторство та copyright/SPDX notices;
3. список змінених файлів і короткий опис адаптації;
4. локальні позитивні/негативні тести;
5. ABI/формат/ownership сумісність та відомі обмеження.

Пін джерела — відтворюваність походження, не заборона оновлень. Оновлювати його можна прямим fast-forward у чинному `main` за правилами репозиторію.

## 4. Зафіксоване Lazarus source

`external/wsm-lazarus` посилається на `juv4uk/wsm-lazarus` commit  
`f5f795ce095f301e987d74aed57948d1bc4e137c`.

Цей пін дає відтворюване джерело Pascal-компонентів, тестів, benchmark harness і механізмів перевірки provenance. Його власний license notice «ВОЛЬНІСТЬ» має зберігатися при копіюванні; це не MIT і не слід називати його MIT.

Важливо: цей Lazarus commit містить власний вкладений SENS pin `2c498b35af53c085450eac6f51b87facf7f9aa47`, пов'язаний із його Contract 9.0 baseline. Він не замінює SENS Contract 12.0 у `wsm-os-lisp`. Семантична влада залишається у чинного upstream SENS Contract 12.0.

Код із Lazarus не відкидається через мову. Водночас конкретні модулі можуть вимагати семантичної адаптації: `wsm.domain.pas` — кандидат для перенесення host-механізму після адаптації під Contract 12.0; `wsm.registry.pas` і `wsm.eval.pas` містять SID8-механізми й не повинні бути підключені як активний evaluator без міграції та conformance evidence.

## 5. Що не змінюється

Ця директива знімає саме мовні заборони. Вона не змінює:
- SENS Contract 12.0 і його семантичну владу;
- target ABI, boot contract та фактичний стан runtime;
- вимоги безпечних апаратних операцій, bounded I/O та захисту даних;
- необхідність тестів, provenance та evidence gates.

## 6. Перевірка

`scripts/check-language-policy.sh` перевіряє, що активна політика не забороняє мови, а gitlink `external/wsm-lazarus` точно збігається з SHA у `refs/wsm-lazarus-pin.lisp`.
