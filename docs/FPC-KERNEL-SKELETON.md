# Pascal on the target: five RTL hooks and a byte-identical transcript
*Pascal на цілі: п'ять хуків RTL і побайтово той самий транскрипт*

**Дата**: 2026-11-27
**Статус**: EVIDENCE — вимір, не рішення. Закриває [ADR-006](../ADR-006-FPC-AS-FOUNDATION-PROPOSAL.md) фазу **P1**.
**Задачі**: `WSM-OS-FPC-KERNEL-SKELETON` (P1), спирається на `WSM-OS-FPC-TOOLCHAIN-PROBE` (P0)

---

## 1. Що саме доведено

Три речі, кожна перевіряється окремо:

| Твердження | Як перевірено |
| --- | --- |
| Pascal-об'єкт лінкується нашим `src/linker.ld` **без жодного undefined-символа** | `nm -u target/kernel-x86_64` порожній, гейт падає інакше |
| Pascal викликає асемблерний runtime через незмінний ABI | `wsm_entry(ctx)` викликає `wsm_cons(ctx, sym1, sym2)` |
| Транскрипт **побайтово** той самий, що в рукописної асемблерної фікстури | `WSM-OS RESULT schema=1 value=(sym1 . sym2) status=ok` |

Третій пункт — головний. Обидві реалізації не просто «обидві працюють»: вони
узгоджені щодо представлення слів, тегів і конвенції виклику, і саме це робить
зріз паритетним свідком, а не демонстрацією.

```text
$ bash scripts/check-fpc-kernel-skeleton.sh
PASS pascal-entry  WSM-OS RESULT schema=1 value=(sym1 . sym2) status=ok
PASS undefined     none (nm -u on target/kernel-x86_64 is empty)
FPC-KERNEL-SKELETON-PASS: FPC 3.2.2, freestanding link, transcript parity with the asm fixture
```

## 2. Мінімальний RTL — це п'ять символів, а не «RTL»

P0 показав, що будь-яка програма FPC тягне рівно п'ять посилань. `src/rtl_min.s`
реалізує їх як no-op і цим закриває межу:

| Символ | Що це | Що робить тут |
| --- | --- | --- |
| `fpc_initializeunits` | ініціалізація юнітів | `ret` |
| `fpc_do_exit` | вихід програми | `ret` |
| `INIT$_$SYSTEM` | ініціалізатор системного юніта | `ret` |
| `FINALIZE$_$OBJPAS` | фіналізатор objpas | `ret` |
| `THREADVARLIST_$SYSTEM$indirect` | таблиця threadvar | один `.quad 0` |

Це чесне визначення «мінімального RTL» для цього зрізу: хуки існують, щоб об'єкт
лінкувався, і **нічого не роблять**. Немає рядків, вводу-виводу, винятків, купи й
стану юнітів. Кожна нова послуга має додаватися в цей файл явно й зі свідком —
цінність файлу в тому, що поверхня **порахується**: п'ять символів, а не «RTL».

## 3. Чого це не доводить

- **Не доводить, що FPC готовий до рівня 2 ADR-006.** Драйвери, менеджер пам'яті,
  GC та image loader потребують того, чого тут немає: роботи з пам'яттю, рядків,
  структур із динамічним розміром, обробки помилок.
- **Не доводить продуктивність.** Це один виклик, не бенчмарк.
- **Не доводить відсутність прихованих залежностей.** `nm -u` порожній на
  **фінальному** образі; окремі об'єкти все ще посилаються на п'ять хуків, і саме
  тому гейт перевіряє фінальний лінк, а не об'єкт.
- **Не скасовує `src/runtime.s`.** Механізм лишається асемблерним, доки P3 не
  перенесе його; P1 доводить лише здатність Pascal жити в тому самому образі.

## 4. Конвенція виклику

Однакова для обох реалізацій, і саме вона робить паритет можливим:

```text
ctx   -> %rdi
word1 -> %rsi
word2 -> %rdx
result<- %rax
```

FPC на x86_64-linux використовує System V AMD64, тому `cdecl; external name
'wsm_cons'` дає рівно те, що очікує `src/runtime.s`. Ніяких адаптерів, ніяких
обгорток — якщо колись знадобиться адаптер, це буде сигналом, що ABI поїхав.

## 5. Відтворення

```bash
sudo apt-get install -y --no-install-recommends \
  qemu-system-x86 ovmf mtools dosfstools gdisk binutils fp-compiler
bash scripts/check-fpc-kernel-skeleton.sh
```

Версія компілятора зафіксована в гейті (`WSM_FPC_VERSION`, типово `3.2.2`):
інша версія — це FAIL, а не попередження. Шляхи можна задати явно через
`FPC_PPCX64` і `FPC_UNITS_DIR`, інакше гейт шукає стандартні.

## 6. Далі (P2)

P2 — це вже не «Pascal запускається», а **той самий сценарій двічі**: boot → одна
форма → одна алокація → один умовний вихід, на Pascal і на ASM+Lisp, з
порівнянням транскриптів і заміром циклу правка→збірка→перевірка. Без заміру
P2 не закривається: саме він перетворює «швидка компіляція» з гасла на число.

## Українською: одне речення

Pascal-функція `wsm_entry` тепер завантажується в тому самому UEFI-образі, викликає
асемблерний `wsm_cons` і дає побайтово той самий транскрипт, що рукописна
асемблерна фікстура; ціною є п'ять no-op хуків RTL у `src/rtl_min.s`, і саме ця
порахована поверхня — головний результат, а не сам факт запуску.
