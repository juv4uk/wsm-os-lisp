# Архітектура обчислювальної екосистеми — потоки й залежності (2026-09-15)

![Моя обчислювальна екосистема — архітектура, залежності та потік даних](architecture/computing-ecosystem-architecture.png)

Схема архітектури повного стеку, авторства власника: від семантики Lisp до
заліза. Цей репозиторій (`wsm-os-lisp`) — це шар **Target Runtime / OS** на
схемі: він реалізує ABI (`wsm_mmio_*`, `wsm_pci_*`, `wsm_*` syscalls), до
якого `CML` емітує виклики, володіє системою виконання (пам'ять, GC,
потоки), OS-інтерфейсом (процеси, I/O, пристрої), драйверами/пристроями
(PCI, MMIO, virtio) та підтримкою платформи — і саме він володіє конкретним
доступом до пристроїв, а не `my-lisp` чи `CML`. Згідно ADR-004, поведінка
production kernel/системи — це Lisp; незвідний фізичний механізм — x86-64
асемблер — жодного C/Rust evaluator/runtime в канонічній цілі, якщо це
окремо не перератифіковано.

Повний стек, згори донизу: Користувач/розробник → **my-lisp** (Мова та
семантика, володіє Canon/значенням) → **CML** (компілятор для My Lisp,
споживає семантику Lisp + перевірені CPU-профілі, ніколи не перевизначає
значення) → **Target Runtime / OS** (цей репо) → Залізо (x86-64 CPU,
пристрої, FPGA).

Ця схема — знімок наміру, а не сама по собі авторитетний документ:
`juv4uk/ecosystem#7` (жива крос-репо карта) лишається авторитетним,
оновлюваним на місці джерелом істини про поточне володіння та межі.
