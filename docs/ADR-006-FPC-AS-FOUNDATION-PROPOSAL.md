# ADR-006: Free Pascal as the OS foundation — proposal, not decision
*ADR-006: Free Pascal як основа ОС — пропозиція, а не рішення*

**Date/Дата**: 2026-11-26
**Status/Статус**: **PROPOSED** — не чинний, не змінює [ADR-004](ADR-004-LISP-ASSEMBLY-PURE-ARCHITECTURE.md), не дозволяє Pascal або C у production-межі
**Supersedes/Заміщує**: нічого
**Related**: [ADR-005](ADR-005-TRUST-BOUNDARY-ARBITER-NOT-KERNELLESS.md), [research/FPC-AS-OS-SUBSTRATE-2026-11-26](research/FPC-AS-OS-SUBSTRATE-2026-11-26.md), [research/PRIOR-ART-NO-KERNEL-2026-11-26](research/PRIOR-ART-NO-KERNEL-2026-11-26.md), `juv4uk/wsm-lazarus` (`docs/decisions/2026-09-18-fpc-first-vertical-ADR.md`, PROPOSED)

## 1. Why this ADR exists / Навіщо цей ADR

Власник сформулював бачення, у якому **Free Pascal стає несучою основою** Lisp-машини: Pascal — ядро, драйвери, менеджер пам'яті, GC, image loader; C — через FFI; SENS — політики; Lisp — інтерактивне середовище.

Це архітектурна теза. За правилами репозиторію вона не може жити в чаті, у промпті для агентів або в коментарі до коду — вона мусить бути ADR. Цей файл фіксує її **як пропозицію**, щоб:

* рішення було явним і датованим;
* було видно, що саме воно змінює;
* жоден агент не почав впроваджувати його «бо промпт», поки власник не ратифікував.

## 2. What it would change / Що воно змінює

| Артефакт | Зараз (ADR-004) | Після ратифікації |
| --- | --- | --- |
| Production-межа | Lisp-політика + x86-64 асемблерний механізм, `RUST = 0`, нуль C | додається третя мова реалізації (Pascal) і четверта (C через FFI) |
| `repo.lisp` | `(capabilities x86_64 assembly …)`, `(non-authorities …)` | перелік мов і авторитетів переписується |
| `scripts/check-no-rust.sh` | забороняє Rust-прошарок | мусить стати «мовний allow-list» |
| `scripts/check-role-authority.sh` | перевіряє рольові межі | потребує нової таблиці ролей |
| `src/runtime.s` | єдиний механізм | стає bootstrap-мінімумом під Pascal-шар |
| `docs/TARGET-ABI.md`, `target-abi-pin.lisp` | ABI v8 під Lisp+ASM | потребує ревізії під Pascal ABI/RTL |
| `tasks.lisp` | DAG під Lisp+ASM | переписується значна частина |

Це не «додати компілятор у CI». Це заміна несучої конструкції, і саме тому рішення належить власнику.

## 3. What blocks it today / Що блокує зараз

1. **ADR-004 (ACCEPTED)** прямо забороняє третю мову реалізації в production. ADR-006 не може «перекрити» його, поки не ратифікований — інакше два чинні ADR суперечать один одному.
2. **Роль FPC у екосистемі вже визначена інакше.** `wsm-lazarus` має PROPOSED-ADR, де FPC — **свідок** канону SENS (статистична компіляція, детермінована пам'ять, арена, trampoline), а не основа системи. «Свідок» і «основа» — різні ролі одного інструмента.
3. **Головний аргумент не виміряний.** «FPC компілює за секунди → швидша ітерація архітектури» — єдиний аргумент, здатний переважити ADR-004. У цій екосистемі він формалізований (`wsm-lazarus`, лінія RAPL), але **заміру циклу «правка → збірка → перевірка» немає**. Правило репозиторію: невиміряне не подається як перевага.
4. **ADR-005 D3.** «Один довірений світ» дозволено *назвати*, але заборонено виводити з нього гарантії. Формулювання «когерентність замість ізоляції» як перевага — саме те, що D3 забороняє цитувати без свідка.

## 4. What would settle it / Що вирішить питання

Не думка, а вимір і вертикальний зріз:

| Крок | Що дає | Де |
| --- | --- | --- |
| W1. Замір циклу | час «правка → збірка → перевірка» для трьох конфігурацій: (a) поточна ASM+Lisp, (b) Pascal-зріз, (c) C-зріз | `wsm-lazarus/METHODOLOGY.md` |
| W2. Енергія ітерації | джоулі на цикл + час людини, окремо від джоулів на виконанні | лінія RAPL, там само |
| W3. Вертикальний зріз | один і той самий сценарій (наприклад, boot → REPL → одна алокація → один умовний вихід) на Pascal і на поточному ASM+Lisp, з однаковим транскриптом | цей репозиторій, новий `nucleus`-свідок |
| W4. Ціна межі | скільки C і скільки Pascal реально потрібно, щоб зріз W3 запрацював; чи лишається межа «політика/Lisp» | цей репозиторій |

Поки W1–W4 не виконані, теза лишається тезою. Це не бюрократія: три з чотирьох пунктів — це рівно те, що власник уже вимагав у `AGENTS.md` («evidence per claim»).

## 5. Options / Варіанти рішення власника

| Варіант | Що означає | Наслідки |
| --- | --- | --- |
| **A. Відхилити** | FPC лишається свідком у `wsm-lazarus`; ADR-004 чинний | нуль робіт тут; ADR-006 → REJECTED |
| **B. Відкласти до виміру** | ADR-006 лишається PROPOSED; спершу W1–W4 | роботи: W3/W4 у цьому репо, W1/W2 у `wsm-lazarus` |
| **C. Ратифікувати** | FPC стає основою; ADR-004 → SUPERSEDED | переписати `repo.lisp`, `check-no-rust`, `check-role-authority`, ABI-док і `tasks.lisp`; усі QEMU-свідки переїжджають під Pascal-шар |

Рекомендація агента (не рішення): **B**. Вона не витрачає нічого, крім одного зрізу, і дає власнику цифри замість переконань.

## 6. What is adopted regardless / Що приймається незалежно від рішення

Процесна частина промпту не залежить від мови реалізації і вже внесена в `AGENTS.md`:

* Definition of Done (8 пунктів);
* формат задачі (рівень / user journey / fail-safely / evidence-план / вплив / ADR);
* правило «evidence per claim»;
* тригери зупинки для fail-safely;
* «вертикальний зріз замість великої фічі» і «ескалюй, а не роби тимчасово».

Це саме те, що робить обидва варіанти (A і C) перевірюваними.

## Українською: одне речення

Пропозиція «FPC — основа системи» зафіксована як **PROPOSED** ADR, а не як рішення, бо вона скасовує чинний ADR-004, змінює роль FPC у екосистемі (`свідок` → `основа`) і спирається на аргумент швидкості ітерації, який у нас досі не виміряний; процесні ж вимоги промпту (DoD, формат задачі, evidence, fail-safely) прийняті одразу, бо вони не залежать від мови.
