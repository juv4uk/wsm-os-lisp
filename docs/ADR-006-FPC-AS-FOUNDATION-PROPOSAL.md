# ADR-006: Free Pascal as the OS foundation — proposal, not decision
*ADR-006: Free Pascal як основа ОС — пропозиція, а не рішення*

**Date/Дата**: 2026-11-26
**Status/Статус**: **PROPOSED** — не чинний, не змінює [ADR-004](ADR-004-LISP-ASSEMBLY-PURE-ARCHITECTURE.md), не дозволяє Pascal або C у production-межі
**Supersedes/Заміщує**: нічого
**Related**: [ADR-005](ADR-005-TRUST-BOUNDARY-ARBITER-NOT-KERNELLESS.md), [research/FPC-AS-OS-SUBSTRATE-2026-11-26](research/FPC-AS-OS-SUBSTRATE-2026-11-26.md), [research/PRIOR-ART-NO-KERNEL-2026-11-26](research/PRIOR-ART-NO-KERNEL-2026-11-26.md), `juv4uk/wsm-lazarus` (`docs/decisions/2026-09-18-fpc-first-vertical-ADR.md`, PROPOSED)

---

## 1. Why this ADR exists / Навіщо цей ADR

Власник сформулював бачення, у якому **Free Pascal стає несучою основою** Lisp-машини: Pascal — ядро, драйвери, менеджер пам'яті, GC, image loader; C — через FFI; SENS — політики; Lisp — інтерактивне середовище.

Це архітектурна теза. За правилами репозиторію вона не може жити в чаті, у промпті для агентів або в коментарі до коду — вона мусить бути ADR. Цей файл фіксує її **як пропозицію**, щоб:

* рішення було явним і датованим;
* було видно, що саме воно змінює;
* жоден агент не почав впроваджувати його «бо промпт», поки власник не ратифікував.

## 2. What it would change / Що воно змінює

| Артефакт | Зараз (ADR-004) | Після ратифікації |
| --- | --- | --- |
| Production-межа | Lisp-політика + x86-64 асемблерний механізм, `RUST = 0`, нуль C | додається третя мова реалізації (Pascal) і четверта (C через FFI) |
| `repo.lisp` | `(capabilities x86_64 assembly …)`, `(non-authorities …)` | перелік мов і авторитетів переписується |
| `scripts/check-no-rust.sh` | забороняє Rust-прошарок | мусить стати «мовний allow-list» |
| `scripts/check-role-authority.sh` | перевіряє рольові межі | потребує нової таблиці ролей |
| `src/runtime.s` | єдиний механізм | стає bootstrap-мінімумом під Pascal-шар |
| `docs/TARGET-ABI.md`, `target-abi-pin.lisp` | ABI v8 під Lisp+ASM | потребує ревізії під Pascal ABI/RTL |
| `tasks.lisp` | DAG під Lisp+ASM | переписується значна частина |

Це не «додати компілятор у CI». Це заміна несучої конструкції, і саме тому рішення належить власнику.

## 3. What blocks it today / Що блокує зараз

1. **ADR-004 (ACCEPTED)** прямо забороняє третю мову реалізації в production. ADR-006 не може «перекрити» його, поки не ратифікований — інакше два чинні ADR суперечать один одному.
2. **Роль FPC у екосистемі вже визначена інакше.** `wsm-lazarus` має PROPOSED-ADR, де FPC — **свідок** канону SENS (статистична компіляція, детермінована пам'ять, арена, trampoline), а не основа системи. «Свідок» і «основа» — різні ролі одного інструмента.
3. **Головний аргумент не виміряний.** «FPC компілює за секунди → швидша ітерація архітектури» — єдиний аргумент, здатний переважити ADR-004. У цій екосистемі він формалізований (`wsm-lazarus`, лінія RAPL), але **заміру циклу «правка → збірка → перевірка» немає**. Правило репозиторію: невиміряне не подається як перевага.
4. **ADR-005 D3.** «Один довірений світ» дозволено *назвати*, але заборонено виводити з нього гарантії. Формулювання «когерентність замість ізоляції» як перевага — саме те, що D3 забороняє цитувати без свідка.

## 4. What would settle it / Що вирішить питання

Не думка, а вимір і вертикальний зріз:

| Крок | Що дає | Де |
| --- | --- | --- |
| W1. Замір циклу | час «правка → збірка → перевірка» для трьох конфігурацій: (a) поточна ASM+Lisp, (b) Pascal-зріз, (c) C-зріз | `wsm-lazarus/METHODOLOGY.md` |
| W2. Енергія ітерації | джоулі на цикл + час людини, окремо від джоулів на виконанні | лінія RAPL, там само |
| W3. Вертикальний зріз | один і той самий сценарій (наприклад, boot → REPL → одна алокація → один умовний вихід) на Pascal і на поточному ASM+Lisp, з однаковим транскриптом | цей репозиторій, новий `nucleus`-свідок |
| W4. Ціна межі | скільки C і скільки Pascal реально потрібно, щоб зріз W3 запрацював; чи лишається межа «політика/Lisp» | цей репозиторій |

Поки W1–W4 не виконані, теза лишається тезою. Це не бюрократія: три з чотирьох пунктів — це рівно те, що власник уже вимагав у `AGENTS.md` («evidence per claim»).

## 6. What is adopted regardless / Що приймається незалежно від рішення

Процесна частина промпту не залежить від мови реалізації і вже внесена в `AGENTS.md`:

* Definition of Done (8 пунктів) — і **пункт 5 уже має зуби**: `scripts/check-docs-in-change.sh` валить збірку, якщо пуш змінює `src/` або `scripts/` без зміни документації; виняток — явний маркер `DOCS-NOT-REQUIRED: <причина>`;
* формат задачі (рівень / user journey / fail-safely / evidence-план / вплив / ADR);
* правило «evidence per claim»;
* тригери зупинки для fail-safely;
* «вертикальний зріз замість великої фічі» і «ескалюй, а не роби тимчасово».

Це саме те, що робить обидва варіанти (A і C) перевірюваними.

## 6.1. Definition of Done: стан кожного з восьми пунктів

Промпт вимагає виконати **все** вісім. Ось чесний стан, пункт за пунктом, і чим кожен примушується.

| # | Пункт DoD | Стан | Чим примушується |
| ---: | :--- | :--- | :--- |
| 1 | Визначено рівень (asm / Pascal / C / SENS / Lisp) | **примусове для нових задач** | `scripts/check-task-format.py`: нове завдання без `(level . …)` валить збірку |
| 2 | Описано user journey | **не примусове** | немає гейта; лишається вимогою до автора задачі |
| 3 | `fail safely` тригери й повідомлення | **примусове для нових задач** | `(fail-safely . (…))` обов'язкове; для MMIO діють 4 політики `mmio-*` |
| 4 | Evidence додано | **примусове** | 13 політик реєстру; кожна перевіряється проти дерева |
| 5 | Docs оновлено в тому ж коміті | **примусове з 2026-11-26** | `scripts/check-docs-in-change.sh`: код без документації валить збірку; виняток — явний маркер `DOCS-NOT-REQUIRED: <причина>` |
| 6 | Швидкість циклу не сповільнилася | **не примусове, і не виміряне** | протокол є в `wsm-lazarus/docs/chas-iteratsii.uk.md`, замірів — нуль |
| 7 | ADR оновлено, якщо рішення архітектурне | **не примусове** | немає гейта; цей ADR — приклад, що це робиться вручну |
| 8 | Жодних «тимчасових» обходів | **частково** | `check-no-rust.sh`, `check-semantic-authority.sh` (заборона float-обходів), маркування LEGACY |

Підсумок: **3 із 8 примусові, 1 частково, 4 ні.**

Два зауваження, які варто тримати в голові:

- пункти 1 і 3 примусові **лише для нових задач** — 55 задач, написаних до правила, внесені в `task-format-disposition.lisp` як legacy. Список перевіряється в обидва боки: якщо legacy-задача отримує поля, вона мусить зі списку зникнути;
- пункт 6 вимагає виміру, якого в екосистемі ще немає. Тобто DoD вимагає того, що ми поки не вміємо довести — і це не привід вважати пункт виконаним.

## 7. Три конфлікти всередині самої пропозиції
*Three conflicts inside the proposal itself*

### 3.1. «Немає перемикання контексту» — але воно в черзі робіт

Пропозиція каже: немає «процесів», «системних викликів», «перемикання контексту» в розумінні Unix. Межа тут тонка й важлива:

- **перемикання домену захисту** — справді відсутнє, і ADR-005 D3 це фіксує («один довірений світ»);
- **перемикання стеків і задач** — не відсутнє: [#99](https://github.com/juv4uk/wsm-os-lisp/issues/99) `[M3-CONTEXT-SWITCH-1] Two independent stacks with timer-triggered bounded scheduler handoff` — це відкрита робота, а [#78](https://github.com/juv4uk/wsm-os-lisp/issues/78) уже має свідка таймерного субстрату.

Тобто формулювання «немає перемикання контексту» описує бажане, а не наявне. Для документа, який дають агенту перед роботою, це небезпечно: агент може вирішити, що планувальник не потрібен.

### 3.2. «Не вводити capabilities» — але capability уже в ABI

Пропозиція забороняє «приховані привілеї (capabilities, ring levels, magic режими)». У нашому ABI capability — не прихований привілей, а **явний, з nonce, і перевіряється гейтом**:

```text
| `capability` | `110` | opaque, nonce-bearing substrate capability descriptor |
Value wsm_pci_config_capability(RuntimeContext *);
Value wsm_mmio_capability(RuntimeContext *);
```

`scripts/check-semantic-authority.sh` вимагає наявності `wsm_pci_config_capability` і конкретного nonce `0x150434954346` у `src/runtime.s`. Тобто заборона слушна лише в читанні «**приховані** capabilities»; у читанні «жодних capabilities» вона забороняє те, що вже прийнято й доведено.

### 3.3. Ціна, названа самими супровідниками FPC

Найважливіше, і це не думка, а першоджерело. FPC wiki, сторінка *Minimal RTL*, на питання «я хочу спеціальний RTL, що робити?» відповідає: *«There is none — you will have to create your own»*, і далі: *«we currently don't really support embedded programming with the existing RTL (at least not the kind where 50kb code overhead matters)»*.

Практично це означає: **хост-мова FPC для ядра = власний RTL**, який треба написати й утримувати. Це не аргумент проти — Ultibo саме так і зробив — але це обсяг роботи, який має бути названий до підпису, а не виявлений на третьому місяці.

Стан інструментарію на 2026-11-26: стабільна гілка — 3.2.2 (3.2.4 RC2 готується з квітня 2026), розробка — 3.3.x trunk; з'явилися щоденні збірки `x86_64-embedded`, але в дереві `rtl/embedded` є aarch64, arm, avr, i386, riscv32, xtensa — **окремого x86_64 RTL там немає**. Тобто наша цільова архітектура — не та, де в FPC вже все готово.

Джерела: wiki.freepascal.org/Minimal_RTL; freepascal.org/develop.html; gitlab.com/freepascal.org/fpc/source/-/tree/main/rtl/embedded; downloads.freepascal.org/fpc/snapshot/trunk/x86_64-embedded/.

## 8. Статус кожного пункту пропозиції — чекліст для агента

Цей текст надіслано повторно, тому найкорисніше — перетворити його на таблицю, яку агент може застосувати **сьогодні**, не чекаючи рішення. Чотири статуси:

- **ЧИННЕ** — уже є правилом у цьому репозиторії, нічого не треба;
- **ПРИЙНЯТИ** — не суперечить нічому, можна брати без підпису;
- **КОНФЛІКТ** — суперечить ADR-004 або ADR-005, потребує рішення власника;

## Українською: одне речення

Пропозиція «FPC — основа системи» зафіксована як **PROPOSED** ADR, а не як рішення, бо вона скасовує чинний ADR-004, змінює роль FPC у екосистемі (`свідок` → `основа`) і спирається на аргумент швидкості ітерації, який у нас досі не виміряний; процесні ж вимоги промпту (DoD, формат задачі, evidence, fail-safely) прийняті одразу, бо вони не залежать від мови.
